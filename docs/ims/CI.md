# Rackelto CI — review specification
Baseline: original 9c74d89 source archive plus Core, Hotfix and Compliance patches (production commit 7989854 as reported by operator). No production source changes. CI uses Node 20, MySQL 8.0 service, Chromium, synthetic credentials, SMTP disabled. Existing Node tests preserved. No live data or deployment secrets needed. Run on PR and main; a push-triggered job alone is not a deployment gate.

## Implemented executable checks
- 32 existing tests: document payload bytes/hash, invalid file names/types/signatures/base64/size, document state transitions, additive schema, JS syntax, mail templates, HTML presence, schema entities, migration mock lock/readiness/retry, compliance contracts and structural checks. Exact test names available via `node --test tests/*.test.js`.
- Packaging (3): admin, partner and corporate build isolation on temporary copies, required assets retained.
- Live API (6 test groups): authentication/CSRF/invalid credentials/revocation/viewer restrictions/logout; legacy schema upgrade/repeat migration/user preservation; application consent/registration/approval/enquiry/outbox; customer/project/work-order creation/offer/acceptance/in-progress/completion; document creation/approval bypass/draft evidence rejection/submit/approve/download byte equality/assessment/risk closure/revision supersession/tamper detection/event existence; Chromium login/dashboard/navigation to all three IMS screens/logout/no uncaught page errors.
- Dependency audit JSON, nonblocking intentionally because existing high-severity findings are unresolved. Coverage report is informational, no threshold yet. Reports retained 30 days. No certification claims.

## Release gate
Use a PR branch; push ZIP only to that branch. Run Actions quality-gate. Configure main branch protection/ruleset to require PR and status check `quality-gate`, prevent bypass including administrators where supported. Private repository protection depends on GitHub plan. If unavailable, disable Hostinger auto-deploy and manually deploy only a tested SHA. Hostinger deploys main; merging is the trigger, not Actions. Verify deployed commit and runtime logs/health/IMS screens; database backup before releases that migrate. CI does not perform production migration or deploy. Do not use `npm audit fix --force` blindly.

## Known risks to review
Current implementation allows self-review (logged), and legacy work-order creation/status logic may permit bypasses. Verified assessment can remain recorded after evidence supersession; later reassessment rejects it but dashboard gap propagation requires a fix. Test DB fixture deliberately uses fake records. Live tests not executed in authoring environment due to unavailable dependency cache/MySQL/browser. Playwright install is pinned but transitive tooling not locked in repository; future lock dev dependencies. Existing portal setup script deletes HTML files for noncorporate builds; packaging checks isolate these changes. No production changes in this ZIP.
